# PILL 桌面助手 0.2.1

> **下载**：[Windows 便携版与源码包](https://github.com/HappyAny/pill-manager/releases/latest) · **许可**：GPL-3.0-only；第三方组件保留各自许可。

MOONDROP PILL 的非官方 Windows 本地管理工具。已在一台实际 PILL（固件 **1.6.0**）上验证。无需手机常驻，也不依赖云服务。

## 0.2.1 单文件便携版

直接双击 `dist/standalone/PILL.exe`。只需这一个文件，不需要旁边放 DLL，也不需要安装 .NET。EXE、标题栏和任务栏使用同一套蓝色耳机图标，含 16～256 像素的九种尺寸。

.NET 的原生运行库会自动解压到 Windows 临时缓存，个人设置备份仍按下文规则保存。便携表示分发时只有一个 EXE，不表示运行时完全不写磁盘。右上角“关于与许可证”可以查看内置许可。

[单文件验证记录](docs/PORTABLE-0.2.1.md)。旧版本文件与备份均保留。

## 0.2.0 界面更新

参考 PCM-A10 工具的紧凑布局，改为原生 WPF Fluent 控件。默认窗口 620×660，最小 540×540，标题简化为 PILL。连接与断开共用一个按钮；电量使用图标和百分比显示。均衡器、触控、设备设置分成四个页签，增益档位和诊断详情可以折叠。

右上角齿轮菜单可选择跟随系统、浅色、深色，或打开 Windows 设置与备份目录。小窗口通过纵向滚动访问完整内容。主题切换不修改 Windows 系统主题。

[浅色预览](docs/previews/light-0.png) · [深色预览](docs/previews/dark-0.png) · [本次界面验证](docs/UI-0.2.0.md)。预览图片明确使用本地示例数据，未连接设备。

## 启动

1. 打开 `dist/standalone/PILL.exe`，或解压 0.2.1 发布包后双击其中的 `PILL.exe`。
2. 将耳机取出盒子，在 Windows 中正常配对音频；关闭手机端占用管理连接的 MOONDROP App。
3. 点击设备列表旁的刷新图标（扫描耳机），选择 PILL，再点“连接设备”。启动程序本身不会改写耳机设置。
4. 进入各页修改，点击“应用”后才写入；每次修改前自动备份，写入后读回确认。

系统要求：Windows 10 2004 或更新版本、x64、可用的 BLE 蓝牙适配器。0.2.1 单文件版已内置 .NET Desktop Runtime 10.0.14，无需额外安装运行时。

## 可以做什么

| 功能 | 实现与验证范围 |
|---|---|
| 左右耳电量、固件 | 实机读取；电量每 30 秒刷新一次；未上报值显示未知 |
| 五段参数 EQ | 编辑频率、Q、增益和前级增益；逐段发送、全量读回；实机变更并恢复通过 |
| EQ 预设、增益档位 | 读取设备支持的编号；切换及恢复通过；未知语义保留编号 |
| 触控 | 九类动作的左右耳及手势分配；保留末尾两个模式动作；配置变更及恢复通过 |
| 双设备连接 | 开关及已连接设备名称；开关变更及恢复通过 |
| 提示音 | 开关、音量档位；音量变更及恢复通过；不切换提示音语言/音色 |
| Windows 播放与麦克风 | 只列出活动的 PILL 音频端点；音量、静音；两个端点的音量变更及恢复通过 |
| 媒体键 | 发送系统上一曲、播放/暂停、下一曲；会作用于 Windows 当前媒体会话 |
| 备份、诊断 | 自动备份、JSON 导入预览与恢复、本地诊断导出 |

“连接设备”仅建立 BLE 设置通道；音频配对、连接、输出设备选择仍由 Windows 管理，界面提供设置入口。

## 尚未完成的部分

- 游戏模式独立开关、固件升级、提示音包切换没有适配。升级请用[官方 App](https://moondroplab.com/cn/download)。
- 充电盒电量未得到有效读数，不显示猜测值。模式触控的最后两个动作原样保留。
- 写入只向已验证的固件 `1.6.0` 开放。其他固件尽力读取；格式不兼容时会报错。
- 触控测试验证的是配置字节；未逐一人工敲击耳机验证动作。未验证手机与电脑同时播放的切换体验、主观听感、端到端延迟或长期稳定性。
- 提示音 16 个间隔的换算与实测的 50%、56%、62% 一致，但没有遍历所有档位。
- 静音和媒体键已实现，但没有主动打断用户播放来验证这些动作。界面导入后的整套恢复尚未做一次完整点击回归，底层各设置恢复均已验证。

## 备份与恢复

升级时旧版文件夹中的备份仍保留，可通过“导入预览”选择原 JSON 文件。

默认目录为 `%LOCALAPPDATA%/PillManager/backups/`。若被拒绝访问，会改用程序旁的 `PillManager-data/backups/`。“打开备份目录”会打开实际使用的位置。开发测试可以设置 `PILL_MANAGER_DATA_DIR`。

“导入备份”只加载预览；“应用导入设置”才写入。为避免误用，要求备份的设备和固件与当前设备一致。恢复不是跨多个命令的原子事务；断电/断连时可能只完成一部分，重新连接后可再次导入原备份。

EQ 写入失败时，若连接仍可用，会尝试恢复此前 EQ 与预设，并读回确认。连接已丢失时不会盲目重发。备份保存失败时不会执行设置写入。

备份含设备地址和连接设备名称，属于本地个人配置。诊断导出会省略这些标识；程序不自动上传文件，不自动升级，不安装常驻服务。

## 构建与检查

安装 .NET 10 SDK 后，在项目根目录运行：

```powershell
./build.ps1
# 生成内置运行时的单个 EXE（构建需要 Python，运行 EXE 不需要）
python tools/build_portable.py
# 只运行本地协议检查，不连接耳机
dotnet run --project tests/PillManager.Checks.csproj
# 读取真实耳机；连接成功后会保存本地快照
dotnet run --project tests/PillManager.Checks.csproj -- --live
# 会临时改变 EQ、触控、增益、提示音、双设备和 Windows 音量，并恢复原值
# 仅在耳机空闲且已关闭桌面助手的管理连接时运行
dotnet run --project tests/PillManager.Checks.csproj -- --live --write-tests
```

实测结果见 [验证记录](docs/VERIFICATION.md) 和 [机器可读结果](docs/verification.json)。协议和来源见 [协议笔记](docs/PROTOCOL.md)。测试原始日志与带设备标识的备份保留在本机 `artifacts/`，不进入发布包。

## 源码结构与许可

- `BleTransport.cs`：发现设备、BLE 连接、请求串行化和回复匹配。
- `PillController.cs`：设备状态、读回验证、修改前备份与 EQ 恢复。
- `GaiaProtocol.cs` / `PillState.cs`：报文与数值格式。
- `WindowsAudio.cs`：Windows Core Audio 和媒体键。
- `MainWindow.xaml` / `.xaml.cs`：原生 WPF 中文界面。
